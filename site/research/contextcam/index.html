RESEARCH / 2024

ContextCam: Bridging Context Awareness with Creative Human-AI Image Co-Creation

ContextCam starts image creation from the situation a person is already in. A context-aware, five-agent workflow turns surroundings and intentions into topic choices, generated images and conversational revisions.

Xianzhe Fan, Zihan Wu, Chun Yu, Fenggui Rao, Weinan Shi*, and Teng Tu.

CHI 2024 · Full paper

Project↗Paper↗Code↗Notebook↗

Context collection and the Android interface

The formative study involved 23 participants and identified five context sources: location, screen content, facial expression, weather, and music. Fifteen participants reported difficulty writing suitable prompts. The design therefore supports topic recommendation before image generation, while retaining text, photo, sketch, and voice input for users with a more specific intention.

ContextCam runs as a resizable floating conversation window on Android. Web APIs collect context; a remote server processes it and responds to the client. Screen context includes visible text and the active application, while music context includes the title and artist. The interface distinguishes sources used in a recommendation, irrelevant sources, and sources disabled by the user.

One filtering failure arises when a cat-themed request is made from the mobile home screen and unrelated app-market text enters the input. Passing that text directly into ideation changes the suggested subject. Keeping source selection visible gives the user a way to inspect and correct the information behind a recommendation.

Context selection with two vectors

The Context Selector uses a five-dimensional binary vector in the order location, screen content, facial expression, weather, and music. A 1 includes that source; a 0 excludes it. The prompt defines eight intention modes with standard vectors, including text illustration, architectural design, travel, music, emotion, and weather. If no mode fits, the agent produces a vector from the user’s command.

A secondary vector adds or removes one modality from the standard selection. Topic Agent generates two recommendations from the standard vector and one from the secondary vector. The alternatives consequently vary in their evidence, not only in wording. Users can choose one of the three topics or supply a custom topic; the selected topic is then expanded into a detailed image concept.

In the example below, the standard vector [1,0,1,1,1] excludes a chat shown on screen while retaining location, expression, weather, and music. The secondary vector [0,0,1,1,1] also removes location. The third recommendation can then explore a direction less tied to the bridge where the user is standing. The changed input is visible before any generated image is judged.

The vector describes whether a source participates in this recommendation. It does not, on its own, explain why a source was omitted. The interface therefore keeps relevance and user control distinguishable: a source can be available but irrelevant, or deliberately disabled. This matters when revising a topic because changing the selection should be understandable as an input decision, rather than an unexplained change in the assistant’s suggestion.

Agent responsibilities and image tools

The system divides creation into framing and focusing. Context Selector and Topic Agent form the brief. Artist Agent discusses content, composition, style, and color with the user. Tool Manager selects an operation and prepares its prompt using the current conversation and a tool catalog. Personalization Agent stores preferences for later conversations.

The implementation uses GPT-4 for semantic interpretation and ideation, VisualGLM-6B for describing images, and Stable Diffusion v1.5 with ControlNet for generation and editing. Paint requests image generation, Edit changes an existing image, and Advice asks for creative suggestions. Separating these operations lets a short command select a different tool path without requiring the user to specify model parameters.

In the bridge example, the requested change is a new composition with the earlier Van Gogh style retained. Tool Manager selects ControlNet’s Shuffle model, which rearranges the original image through a random flow, and uses Stable Diffusion to produce the new image. The operation depends on what should change and what should persist; the subject word alone does not specify that.

Tool Manager keeps the current conversation history. Personalization has a different scope: after a satisfactory result or the end of a dialogue, it summarizes subjects, styles, and themes for future Topic and Artist decisions. Preference updating therefore has its own place in the workflow, separate from the current image operation. This is the part I focus on in architectural discussions with collaborators: when the memory is written and which later decisions may use it.

The bridge edit also separates conversation state from the generated asset. To retain a style while changing composition, the tool operation needs the earlier image as well as the new instruction. A summary such as a preference for Van Gogh does not preserve that image’s particular colors and arrangement. The current conversation and image reference therefore support the edit, while the longer-term preference summary supports later recommendations.

Three-day study results

Sixteen participants completed a thirty-minute tutorial, three days of use, a questionnaire, and a follow-up interview. Each held fifteen conversations, giving 240 conversations across 136 distinct contexts. A conversation could include several interactions and images. The study logged dialogue, generated images, and context so that a result could be linked to the recommendation and edits that produced it.

Users selected a recommended topic in 92.9% of conversations. Mean image satisfaction was 5.80 out of 7 (SD 1.17), and perceived ease of use was 5.88 (SD 1.45). The mean ratio of typed input to interaction rounds was 1.1 Chinese characters per round; typed input was counted in Chinese characters. These measures describe topic adoption, satisfaction, and input burden in the deployed system.

Twelve conversations received satisfaction scores below 4. Five involved malformed hands or feet; the others concerned cultural mismatch (three), divergence from a familiar scene (two), and missing model knowledge (two). These failures occur after context selection: an appropriate topic can still produce an image that misunderstands a place or visual tradition. Retaining the dialogue and source context makes those failures distinguishable from an irrelevant recommendation.

Only four conversations omitted all contextual data. As participants became familiar with the system, some selectively disabled inputs such as location or screen content. The control over sources was therefore used during creation, rather than serving only as an initial setup screen.
