Swim the World

泳动世界 · 召唤海洋小精灵

An AI co-creation installation connecting drawing, generated characters, and shared public displays, with installations in Hangzhou public spaces.

通过绘画、AI 辅助角色生成与公共屏幕连接公众共创，在杭州亚运相关无废空间及西湖区公共场景落地。

Entry, naming, and release

We placed the WeChat QR code at the start of the route. Participants opened the mini program, chose a creative theme, and entered a nickname and character name. Both names continued onto the generated card. Participants could inspect the result there, then slide the control at the bottom to release it into the shared pool.

Release came after preview so participants could see exactly what they were sending to the public screen. In the super jelly example, the name stayed above the character image and in the card details. The label helped connect the transformed character to its contributor when it joined the other drawings.

Drawing controls and interaction states

We kept Switch theme in the lower-left corner of the canvas, Clear near the bottom, and Generate on the lower right. Participants could still change themes while drawing. Generate requested a character card; release belonged to the next screen.

The editable drawing, generated preview, and released public character are different states. I keep editing controls on the canvas and the release control on the card for that reason. Repeated generation changes the candidate image; repeated release concerns an object already on the shared screen. Those actions need separate handling in implementation.

Switch theme opens a selector from the bottom, with Cancel and Done above the choices, while the drawing screen remains behind it. That preserves the current task during a theme change. The later card has a different job: it names and previews the contribution before the slider publishes it. I use the drawing, card name, and visible character to follow one contribution across the screens. A generation retry belongs to the private preview stage; a release retry concerns the shared display. Keeping those points separate makes it possible to diagnose where a contribution stopped without treating the whole journey as one submit action.

Connecting Stable Diffusion to the exhibition

We deployed Stable Diffusion on a computer and connected it to the creation workflow through an API. Participants drew in the mini program, requested generation, and received a character card there. The model ran on the computer behind that interaction; participants never had to leave the drawing flow to operate it.

I see two separate completion points in this setup: getting an image back and seeing a character on the public screen. The API response completes generation and returns the participant to a preview. Releasing the character is still their decision. Keeping that step in the interaction gives them a chance to recognize their drawing in the result before it joins everyone else’s work.

For the next version, I would make the waiting states clearer. Waiting for the computer to finish generation and waiting for a released character to appear are different situations, even though both can look like a stalled screen. I would keep progress and recovery close to the action that triggered them, so the participant knows whether to keep waiting, generate again, or check the public display.

Sketch and generated character

We used the jellyfish example to define the transformation we wanted. The umbrella-shaped outline and tentacles connected the sketch to the generated character; color and surface detail could change around that structure. The preview gave participants a place to check whether the result still resembled their idea. I treat the name and shape as two separate aids: the name identifies a contribution, while the shape helps someone find it in a crowded pool.

Public display and urban participation

We connected exhibition, interaction, co-creation, and a search activity in the proposal. Display structures and a shared screen were accompanied by QR entry points in outdoor settings. The invitation to let children design linked an individual drawing task to an urban co-creation exhibition. The mini program gave those different entry points one creation route.

We used the phone for individual drawing and preview, and the shared screen for the released characters. This let people inspect their own contribution before it joined the collective composition. Across the two screens, the card identity and the character's appearance had to remain recognizable.
